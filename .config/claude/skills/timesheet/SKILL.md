# 稼働勤務表

引数:
- **URL（必須）**: 勤務表のスプレッドシート。無ければ実行せず、URL を聞き返す
- **月（任意）**: `YYYY-MM`。省略時は今月

対象の repo は、実行したディレクトリの git repo（worktree を含む）。GitHub の repo とユーザーは `gh` から取る。

## 1. 集計

```bash
python3 ~/.claude/skills/timesheet/scripts/collect.py 2026-10
```

- 1 時間以内の空きはつなげて 1 つの時間帯にし、両端を近い方の 30 分に丸める。10 分未満の時間帯は捨てる
- 今日は数えない。このセッション自身を拾わないため
- 出力は `## 日付 開始-終了 (h)` と、その時間帯のユーザー発言・コミット件名。日をまたぐ時刻は `25:30` 形式
- `gh` が使えない repo は `--no-github` を付ける
- ログに残らない作業（打ち合わせ、PR を読む時間など）は入らない。ユーザーの体感とずれたら Calendar や Slack で補う

## 2. シートを読む

URL のシートを開き、対象月のタブ（例: `2026/10`）と前月のタブを読む。ページ内で次を実行すると CSV で読める。

```js
await fetch(`/spreadsheets/d/${id}/gviz/tq?tqx=out:csv&sheet=${encodeURIComponent('2026/10')}`).then(r => r.text())
```

- 列構成・日付の式・休憩と勤務時間の式・メモの書き方を、前月のタブから確かめる。下の「入力」はこの構成を前提にしているので、違えば合わせる
- 既に値が入っているセルは、上書きする前にユーザーに確認する

## 3. 確認

時間帯表と、時間帯ごとのメモ案をユーザーに見せ、書き込む前に承認を取る。

- メモは前月の書き方に合わせる（例: `テーマ (#PR): 何をしたか`）。発言とコミット件名から書き、PR タイトルは `gh pr list --author @me` で確認する
- 1 日に時間帯が複数ある日を行を分けて書くかどうか、前月に前例が無ければユーザーに聞く

## 4. 入力（Claude in Chrome）

`list_connected_browsers` が空、または応答がないときは、ユーザーに拡張のサイドパネルを開いてもらう。

想定する列構成: A 日付（`=A前行+1` の式）/ B 曜日 / C 開始 / D 終了 / E 休憩（式）/ F 勤務時間（式 `D-C-E`）/ H メモ / F 列の SUM が合計。

1. **行の追加**: 下の日から順に、名前ボックスで `N:N` を選ぶ → 挿入 → 行 → 下に 1 行挿入。行 N をコピーして新しい行に貼り、新しい行の A を `=A{N}` にする
2. **時間**: 名前ボックスで `C{行}` に移り、列ごとに `値\n値\n…` と入れる。D も同様
3. **メモ**: H 列は 1 セルずつ入れ、Return の前に Delete を押す
4. **検証**: 手順 2 の fetch で読み戻し、各行と合計がユーザーに見せた表と一致するか確かめる

### 落とし穴（実際に踏んだもの）

- `type` に Tab を混ぜると、隣のセルに移らず 1 つのセルに `6:00 9:00` と入る。必ず列ごとに入れる
- メモ列は入力補完が効く。同じ書き出しのメモを Return で確定すると、上の行の文で上書きされる
- `•` は `type` で入力すると落ちる。必要ならユーザーに手で付けてもらう
- 日をまたぐ終了時刻を `1:30` と入れると勤務時間がマイナスになる。`25:30` と入れる
